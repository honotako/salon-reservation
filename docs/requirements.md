# 要件定義

## 1. 目的

個人経営の美容室の予約管理を楽にすること。

## 2. 解決したい課題

- 予約が LINE・電話・Instagram など、別々の場所から届く
- 紙の台帳や記憶で管理しているため、予約の重複や確認漏れが起きやすい
- 空いている時間を、その都度自分で確認しなければならない

## 3. 解決方法

- すべての予約を 1 か所に登録して、一元管理する
- 営業時間・休日・既存の予約から、空いている時間を自動で計算する

## 4. 利用者

| 利用者 | 説明 | 状態 |
|---|---|---|
| 美容師（スタッフ） | 予約の登録・確認・変更、店舗の設定を行う | 実装済み |
| お客様 | Web から予約し、予約の確認・変更・キャンセルを行う | 未実装（次の工程） |

## 5. 機能一覧

### 美容師側（実装済み）

| 機能 | 内容 |
|---|---|
| ログイン／ログアウト | メールアドレスとパスワードで認証する |
| 本日の予約 | 今日の予約一覧と件数（予約中・来店済み）を表示する |
| 予約一覧 | 月表示のカレンダーで予約と休日を表示する。美容師ごとに色分けし、キャンセル・無断キャンセルはグレーで表示する |
| 予約詳細 | 予約とお客様の情報を表示する |
| ステータス変更 | 予約中の予約を「来店済み」「キャンセル」「無断キャンセル」に変更する |
| 予約の削除 | 予約中の予約を論理削除する |
| 予約登録 | 既存のお客様または新しいお客様の予約を、空いている開始時間から選んで登録する |
| 営業時間の設定 | 開店・閉店時刻と予約の刻み（15・30・60 分）を設定する |
| 定休日の設定 | 毎週の定休日（曜日）を設定する |
| 臨時休業日の設定 | 日付と理由を指定して臨時休業日を追加・削除する |

### お客様側（未実装）

| 機能 | 内容 |
|---|---|
| 空き状況の確認 | 予約できない日時はグレーで表示する |
| Web 予約 | 美容師（指名必須）・メニュー・日時を選んで予約する。確認画面を挟む |
| 予約の確認・変更・キャンセル | 来店日の 3 日前まで変更・キャンセルできる |
| メール通知 | 予約完了などをメールで知らせる |

## 6. 業務ルール

| 項目 | ルール |
|---|---|
| 予約の受付 | 先着順。同じ美容師の同じ時間帯には 1 件だけ |
| 指名 | 美容師の指名は必須 |
| 予約の長さ | メニューの所要時間で終了時刻を決める |
| 予約の枠 | 店舗の設定（営業時間・刻み）で開始時刻の候補を作る |
| 埋まっている扱い | 「予約中」「来店済み」は埋まっている。「キャンセル」「無断キャンセル」は空いている |
| 変更できる予約 | ステータス変更と削除は「予約中」の予約だけ |
| 休日 | 毎週の定休日と、臨時休業日の 2 種類。休日は予約できない |
| 予約経路 | スタッフが登録するときは、電話・LINE・Instagram・その他から選ぶ。Web 予約はお客様側から |

## 7. 非機能要件

| 項目 | 内容 |
|---|---|
| 認証 | 美容師用の画面は、ログインしていないと開けない（proxy と layout の 2 段階）。サーバー側の処理でも毎回ログインを確認する |
| データの削除 | 予約・メニュー・美容師は論理削除（削除済みの印を付ける） |
| 時刻 | DB には UTC で保存し、画面と判定は日本時間で行う |
| 同時操作 | ステータス変更・削除は「予約中のときだけ」という条件付きで更新し、別の画面からの同時操作でも不整合が起きないようにする |
| 予約の重複 | 予約を保存する直前に、もう一度空きを確認する |
| 公開 | Vercel ＋ Neon で公開する。main ブランチへのマージで自動で公開される |
